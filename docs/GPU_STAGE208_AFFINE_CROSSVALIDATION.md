# Stage 208 — leave-one-landmark-out similarity versus affine evidence

Stage207 compares per-frame ordinary and reflected 2D similarities, visible
angle/scale variation, and optional temporal lag. A persistent weakness is
that a full 2D affine model can remove both in-plane camera nuisances
and genuine pose/anatomical differences, while fitting the **same** points
used to judge its own correctness. Stage208 evaluates these two models
on **landmarks excluded from fitting**.

**All calculations remain owner-private. Public CI uses only invented
2D correspondences and generated rig/animations. No authentic PS3 frames
were used in the public checks.**

## Cross-validation method

`tools/foj_stage208_private_affine_crosscheck.py` operates on
3–12 Stage196 frames with 5–32 consistent manually labelled,
noncollinear landmarks. Four landmarks are deliberately insufficient:
leaving one out permits an affine model to exactly interpolate three
training correspondences, creating misleading apparent certainty.

For each frame and each held-out landmark:

1. Exclude the chosen landmark from the training correspondences.
2. Fit ordinary and reflected **2D similarity** (translation,
   uniform scale, in-plane rotation) to the remaining points;
   select reflection using **training error only**.
3. Fit a **full 2×2 affine matrix plus translation** to the same
   training points, rejecting singular or extremely distorted maps.
4. Predict the omitted location with each model and measure its
   error, normalized by the full reference-point radius.

Both models receive identical training/held-out partitions.
The report contains per-frame held-out RMS, median values,
affine singular-value anisotropy, orientation-sign consistency and
conservative counts of frames in which affine predictions improve.

Tentative thresholds used by this research-only diagnostic:

- Image-plane source/research geometric conflict if the **better**
  held-out model exceeds 0.18 normalized RMS for a frame.
- A possible affine 2D nuisance requires at least 60% of frames to
  improve, with similarity error at least 0.05 and affine error
  under 0.18. These are heuristics, not source-game fidelity tolerances.
- Low similarity holdout error is labelled
  `two_d_similarity_sufficient`, **not** verified PS3 correctness.
- Capture-declaration absence prevents a positive interpretation.

Reports never export coordinates, private landmark labels or source
images. Mirror preference does not prove handedness; anisotropy is
neither a measured physical camera lens nor proof of 3D viewpoint.

## Offline private usage

```sh
python3 -m tools.foj_stage208_private_affine_crosscheck \
  --observations local-data/observations/pose-landmarks.json \
  > local-data/observations/private-affine-crossvalidation.json
```

To use it in a full Stage203 owner-local native rig/clip audit, pass
`--affine-crosscheck` and all three prerequisite flags:

- `--observations`: operator's paired landmark observations.
- `--source-png-dir` and `--source-png-manifest`: Stage205
  exact content binding to original-side local PNG frames.
- `--frame-bindings`: Stage204 binding to actual research C-rendered
  PPM frames generated by the same Stage203 invocation.

For example:

```sh
python3 -m tools.foj_stage203_private_actor_evidence \
  --rig local-data/rig/preview.fojrm \
  --primary local-data/anims/preview.banim \
  --secondary local-data/anims/preview_b.banim \
  --observations local-data/observations/pose-landmarks.json \
  --source-png-dir local-data/observations/ps3-frames \
  --source-png-manifest local-data/observations/source-png-private.json \
  --frame-bindings local-data/observations/native-frame-binding.json \
  --affine-crosscheck \
  --output-root local-data/stage208-private-evidence
```

The bundle stores `private-affine-crossvalidation.json` as an
owner-only diagnostic and a short diagnosis in
`private-evidence-status.json`. Running without both bound image
sides is **rejected before output creation**. Existing private
owner files are never overwritten. Keep the entire output and its
numeric metrics outside public GitHub and all public CI artifacts.

`--review-overlays` (Stage206) can additionally generate private
numbered paired images. A person should use those to examine wrong
actor/limb, reflection, source camera, occlusions and misleading
correspondences. A good affine fit cannot establish that the selected
joints, source video, timestamps or game animation are authentic.

## Why the output is not original PS3 evidence

Anisotropic scaling or shear in 2D can reflect perspective, camera
motion, actual pose articulation, measurement noise or incorrect
landmark matching. A lower affine holdout residual distinguishes
none of these causes. The comparison has no knowledge of actual
3D camera parameters, original game character/clip IDs, bones,
bind matrices or verified PS3 timing. Even an excellent low-RMS
fit is only a hypothesis about the **operator's annotated pixels**.

Source PS3 gameplay authenticity, true 3D projection, original
animation scheduling and physical Nintendo Switch behavior remain
explicitly unverified.

## CI

`tests/test_foj_stage208_private_affine_crosscheck.py` exercises:
similarity and reflected similarity, invented nonuniform affine
distortion, outliers, insufficient landmarks, degenerate fits, identity
and time schema violations, unrecorded capture declarations, private
CLI output, and fail-closed use in Stage203. It also includes a full
**generated-only** test with Stage203's production C parser, CPU
skinning, native wireframe PPM, paired invented source PNG and
frame bindings. No authentic game files or original captures are
introduced by the public tests.
