# Stage264 — actual generated-alpha cutout and opaque depth counterfactual

Stage263 proved a real per-swapchain Z24S8 GPU depth target with opaque,
overlapping invented triangles. It did **not** prove how transparent
texels interact with depth. Stage264 adds **one separate opt-in research
NRO**, retaining Stage263's near-is-larger GREATER depth comparison but
using a distinct UAM-generated fragment shader:

```glsl
vec4 texel=texture(uResearchMaterial,vUV);
if (texel.a < 0.5) discard;
oColor=texel;
```

Discard must occur *before* a fragment writes to the GPU depth buffer;
otherwise the background material cannot appear through the aperture.

## Native build / shaders

```sh
make -f gpu/alpha_draw.mk verify
make -f gpu/Makefile triangle-verify alpha-verify
```

`foj-deko3d-alpha-cutout-proof.nro` selects
`sdmc:/switch/foj/gpu/foj_alpha_cutout.frag.dksh` only with
`FOJ_GPU_ALPHA_CUTOUT=1`. Existing GPU NRO modes continue reading
`foj_triangle.frag.dksh` unchanged. Both shader binaries must be
generated by UAM (never original PS3 shader bytes).

## Generated-only two-run acceptance test

As in Stage263, near opaque WARM is submitted FIRST, farther solid COOL
SECOND, both as invented FOJRM001 / FOJMAT01 triangles. The only input
difference between the two isolated NeXium sessions is the warm RGBA8
DDS alpha channel:

- **masked:** UV aperture `0.62 ≤ U ≤ 0.77`, `0.59 ≤ V ≤ 0.80`
  contains alpha 0. All other pixels remain alpha 255.
- **opaque:** same 64×64 RGBA8 DDS, all alpha 255.
- All source RGB colors, vertex positions, near/far Z, draw-order,
  material indexes, and UAM fragment shader code remain identical.

A true alpha-discard GPU depth path must produce:

| Predetermined 11×11 pixel neighborhood | Masked | Opaque |
|---|---|---|
| (640,400), overlapping UV aperture | farther COOL | nearer WARM |
| (600,400), overlap outside aperture | nearer WARM | nearer WARM |
| (520,380), warm-only wing | WARM | WARM |
| (760,400), cool-only wing | COOL | COOL |

An independent image checker checks **at least 110 of 121 pixels** in
each neighborhood, zero wrong-material pixels, four authentic 1280×720
NeXium screenshots (2 each scenario), phase change between each pair,
and the exact opposite winners at the aperture location.

Python PIL unit fixtures intentionally simulate the correct pattern
but also reject **no discard**, an erroneously transparent all-opaque
counterfactual, missing rear actor, incorrect material color, duplicate
frame, and absent second capture. PIL images **never** qualify as real
NeXium runtime evidence.

## Evidence limitations

Only fabricated FOJRM001, FOJMAT01, RGBA8 DDS and public UAM DKSH
research artifacts enter public GitHub Actions. The test has no
original Vandal Hearts PS3 character, texture, model or screenshot.

This stage demonstrates **binary alpha cutoff** for a static generated
scene, *not* partial transparency or alpha blending, anti-aliased cutout
edges, original PS3 materials, mesh animation, particle sorting,
physical Switch output, or playable battle scenes. Fail and hold PR if
real guest captures do not match the independent prediction.

The independent inherited Stage261 main-push workflow can occasionally
capture two identical clear-background phases, causing a fail-closed
silhouette check. This new alpha guest uses the Stage263 phase-aware
driver without changing the older workflows or weakening their oracle.
