# Stage 211 — independently bind images for multiple private motion windows

Stage210 compares two to four sequences of operator-annotated motion
while conservatively refusing identical normalized trajectories as
independent. **But annotations alone do not prove that the operator
actually inspected distinct original-side images and experimental
rendered frames.**

Stage211 checks **the source PNG and research C-rendered PPM evidence
for every window**, privately, without any upload or external service.

## Owner-local manifest

Create a **private, ignored** Stage199-format operator observations
JSON containing two to four sequences (each 3–9 annotated frames).
Separately create `local-data/observations/window-image-bindings.json`
with this structure:

```json
{
  "schema": "foj.stage211.private_multisequence_image_evidence.v1",
  "windows": [
    {
      "source_png_dir": "local-data/observations/action-a/source-png",
      "source_manifest": "local-data/observations/action-a/source-manifest.json",
      "research_frames_dir": "local-data/observations/action-a/research-ppm",
      "research_binding": "local-data/observations/action-a/research-binding.json"
    },
    {
      "source_png_dir": "local-data/observations/action-b/source-png",
      "source_manifest": "local-data/observations/action-b/source-manifest.json",
      "research_frames_dir": "local-data/observations/action-b/research-ppm",
      "research_binding": "local-data/observations/action-b/research-binding.json"
    }
  ]
}
```

All paths must remain private, valid and owner-controlled. The JSON
configuration and source manifests must not be committed or attached
to GitHub Actions.

A source manifest for each action can be created using Stage205's
private `--prepare` command against that action's operator
landmarks and separately captured PNG set. Its research frames must
be generated by the Stage203 native C rigged-actor viewer. Stage204
then creates the frame-name binding to the exact experimental
landmarks manually selected on those native PPM images.

## Running the audit

```sh
python3 -m tools.foj_stage211_private_multisequence_image_binding \
  --observations local-data/observations/motion-windows-private.json \
  --bindings local-data/observations/window-image-bindings.json \
  > local-data/observations/private-multisequence-image-audit.json
```

For **every** window, the tool calls:

- Stage205 `inspect_sources` to verify complete PNG content,
  CRC, size, SHA-256, ordering and operator-declared timestamps
  against the private source manifest;
- Stage204 `inspect_landmarks` to verify experimental annotations
  land on **the named native C-rendered wireframe PPM image**, with
  the existing 10-pixel safety tolerance;
- a comparison of source PNG SHA-256 digests *in private memory
  only* across all windows to flag a **byte-for-byte screenshot replay**
  even if names or operator timestamps have been changed.

A repeated source PNG makes the diagnosis
`duplicate_source_png_between_windows` and prohibits treating the
windows as verified independent image samples. This includes some
legitimate static or repeated images, conservatively: the tool does
not try to decide which source-game frames are genuinely distinct.

Successful content binding yields
`source_and_research_images_locally_bound_only`, **never**
`original PS3 motion verified`. Neither image provenance nor
real-game actor, clip, physical PS3 device, camera, anatomy or time
is authenticated.

The audit is **read-only**. It never copies images, writes originals,
publishes private hashes, prints local paths or forwards source
content to an external API. The final JSON contains only counts,
boolean evidence gates and negative authenticity flags.

For full analysis, run the Stage210 multisequence motion check
separately after this image evidence audit. The two stages answer
different questions:

- Stage210: do the annotated motion changes agree, and are
  normalized sequences simply repeats?
- Stage211: were the observations tied to exact, separately stored
  source screenshots and real research-viewer frames?

Both can pass while original PS3 fidelity **remains unverified**.
True evidence still requires genuine, independently reviewed
original-game footage and actor/clip identifications.

## CI testing

`tests/test_foj_stage211_private_multisequence_image_binding.py`
uses **only generated RGB/RGBA PNGs** and synthetic wireframe
PPM images with invented landmarks. Tests cover two and three
windows, replayed PNG bytes, changed/swapped source images,
wrong experimental marks, missing or symlinked files, malformed
manifests, source operator declarations, CLI privacy and no
original PS3 authenticity claims.

No original commercial assets, private source PNGs or
user-specific filenames are included in public CI.
