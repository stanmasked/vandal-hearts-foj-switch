# Stage332 — bounded synthetic DDS source decode

The **private owner-local** source inventory Stage331 observed 1,479 `*.tga`
resources that carry real `DDS ` headers: 988 BGRA8, 15 BGR24, 471 BC1/DXT1,
and 5 BC2/DXT3. Stage332 does not ship or read any PS3 assets.

`gpu/stage332_dds_source.c` is a separate CPU decoder rather than weakening
`gpu/atlas_dds.c`'s already-validated 256x256 atlas boundary. It handles
classic, tightly-packed DDS level 0 of BGRA8, BGR24, BC1 (including 3-color
transparent index), and BC2 (four-color mode with explicit 4-bit alpha).
Base surfaces may have odd dimensions; compressed layouts use ceiling division
into 4x4 blocks. Every declared mipmap level must fit *exactly* in the input
with no hidden bytes. Mipmap tails are validated but not decoded or uploaded.

Bounds: 2048px in either axis, 4,194,304 maximum pixels, 12 mip levels,
16MiB maximum RGBA8 output. Source and destination may not overlap. Invalid
FourCC/masks, unsupported caps/reserved words, unexpected pitch, incomplete
mipmap chains, truncated/extra input and insufficient output capacity are
rejected **before any output pixel or metadata changes**. This module only
accepts memory already supplied by an authorized caller; it performs no file
access or private-data export.

Tests use generated bytes only. They verify the four formats, BC2 alpha
nibbles, BC1 transparency, partial blocks, BGRA/BGR swizzle, chain validation,
and negative/fail-closed scenarios. Independent jobs cover GCC and Clang,
Clang ASan/UBSan, and devkitA64 **cross-compilation only**.

**Non-claims:** Stage332 tests do not demonstrate a real PS3 texture decode,
asset binding, GPU draw, NRO integration, gameplay, or a physical Switch run.
Require isolated private owner-source parity and real GPU observation in later
stages. Preserve original PKG and raw derived assets in owner-only Google Drive;
public GitHub contains only this decoder, synthetic fixtures and documentation.

## Source DDS header shape discovered during the private Stage332 audit

The owner-local Stage331/332 aggregate scan found all 1,479 original DDS
headers use a **zero pitch/linear-size field**, no PITCH/LINEARSIZE header
flag, and (for BGRA32 only) a legacy alpha caps bit `0x2`. Exactly seven
known format/mipmap header combinations were observed. The decoder now accepts
either a fully canonical pitch-and-flags profile or that exact source profile;
hybrid profiles still fail closed. No other flags, pitch padding or channel
masks are relaxed. Added synthetic regression fixtures for both accepted
profiles and deliberately malformed hybrids.

Private read-only metadata recheck: header shape, pixel-format masks,
dimensions, declared complete mip-chain size and reserved/caps checks accepted
1,479 / 1,479 DDS entries. This says nothing about full runtime pixel parity,
texture sampling or physical Switch integration: source bytes remain private.
